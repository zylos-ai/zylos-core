# Decision Topic Page Format

## Purpose and location

Record deliberate choices and their rationale by topic, one topic per page under
`reference/decisions/`. A decision has a clear commitment and closes off
alternatives. Read `reference/decisions/INDEX.md` first, then relevant pages;
when unmatched, Grep the directory including `archive/`, then consult the
read-only old `reference/decisions.md` or `reference/legacy/` before creating a
new topic. See [moving from old files](sync-procedures.md#moving-from-old-files).

Use a short ASCII filename containing lowercase letters, digits and hyphens,
with a `.md` extension and at most 48 characters including the extension.
`INDEX.md` and `archive/` are reserved. Titles may use the topic's own language.
The old file and `legacy/` are read-only history.

## Page header

The header starts on the first line with `# Title` and ends at the first blank
line. The title, exact marker, Status and Updated are required. Scope describes
which decisions belong in this topic, replacing a project page's Description.

```markdown
# JavaScript module policy
<!-- zylos:entry kind=decisions -->
- **Status:** active
- **Updated:** 2026-11-10
- **Keys:** JavaScript, ESM, modules
- **Scope:** Module-system choices for the core codebase
- **Moved from:** decisions.md “ESM-only for core code”

## 2026-11-10
### ESM-only for core code
- **Date:** 2026-11-10
- **Decided by:** Owner
- **Decision:** Use import/export throughout the core codebase.
- **Context:** Keep one module system across maintained code.
- **Status:** active
- **Importance:** 2
- **Type:** procedural
```

Page Status is `active | archived`. Keys contains aliases and identifiers; Moved
from records exact old headings. Individual decisions in the body retain their
own `active | superseded | archived` status. When a decision is superseded, name
its replacement. Importance 1–2 entries are immune to automatic fading
suggestions. See [the single-topic example](../examples/decisions.md).

## Generated directory

Run `reference-index.js rebuild` after writing pages. Do not hand-edit INDEX.md.
It generates both `reference/decisions/INDEX.md` and
`reference/decisions/archive/INDEX.md` from page headers.

```markdown
# Decisions Index
<!-- zylos:index kind=decisions v=1 — generated by reference-index.js rebuild; edit the page headers instead -->
Archived decisions: archive/INDEX.md. If a topic is not listed, Grep reference/decisions/ (including archive/), then the old decisions.md or reference/legacy/.

| Status | Updated | Topic | File | Scope |
|---|---|---|---|---|
| active | 2026-11-10 | JavaScript module policy | javascript-modules.md | Module-system choices for the core codebase |
```

Rows sort by active then archived, and by Updated descending within a status.
Titles are copied with `|` replaced by `／`. Unreadable headers stay out of the
main table and appear under `Unparsable page headers`. Missing indexes are
treated as empty until rebuilt. INDEX warns above 16 KiB and has a 32 KiB budget;
page files have no hard size cap.

## Lifecycle rules

1. “We should…” is an idea, not a commitment. Preferences go in
   `reference/preferences.md`, project status in `reference/projects/`, and
   uncommitted proposals in `reference/ideas.md`.
2. Update the page's Updated and append a dated decision with its rationale.
3. Origin Sync or single global Sync archives a topic when all its decisions
   have been superseded, using
   `reference-index.js archive --path reference/decisions/<page>.md`.
4. When an archived topic is mentioned again, run
   `reference-index.js unarchive --path reference/decisions/archive/<page>.md`
   before updating it. Both moves rebuild the indexes. An existing destination
   returns `EXISTS` without overwriting; rename or merge before retrying.
