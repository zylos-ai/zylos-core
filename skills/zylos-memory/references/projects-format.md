# Project Page Format

## Purpose and location

Record one work effort with a defined scope and lifecycle per page under
`reference/projects/`. Read `reference/projects/INDEX.md` first, then the relevant
pages; when no entry matches, Grep this directory including `archive/`, then
consult the read-only old `reference/projects.md` or `reference/legacy/` before
creating a page. See [moving from old files](sync-procedures.md#moving-from-old-files).

Use a short ASCII filename containing lowercase letters, digits and hyphens,
with a `.md` extension and at most 48 characters including the extension.
`INDEX.md` and `archive/` are reserved. The title may use the project's own
language. The old file and `legacy/` are read-only history.

## Page header and body

The header starts on the first line with `# Title` and ends at the first blank
line. The title, exact marker, Status and Updated are required.

```markdown
# Pages sharing password
<!-- zylos:entry kind=projects -->
- **Status:** active
- **Updated:** 2026-11-10
- **Started:** 2026-08-01
- **Keys:** zylos-pages, share-password
- **Moved from:** projects.md “Pages sharing password”
- **Description:** Password sharing is implemented; waiting for owner acceptance.

## 2026-11-10
- Password sharing passed the agreed checks; owner acceptance remains pending.
```

Status is `active | planning | paused | completed | abandoned`. Keys contains
aliases and identifiers used to match new input. Moved from records the exact
old headings read during migration. Description is one to three lines covering
the goal, current state, next step and whom the work is waiting for. Keep dated
records in the body; existing Importance and Type fields may accompany them.

See [the single-project example](../examples/projects.md).

## Generated directory

Run `reference-index.js rebuild` after writing pages. Do not hand-edit INDEX.md.
It generates both `reference/projects/INDEX.md` and
`reference/projects/archive/INDEX.md` from page headers.

```markdown
# Projects Index
<!-- zylos:index kind=projects v=1 — generated by reference-index.js rebuild; edit the page headers instead -->
Archived projects: archive/INDEX.md. If a project is not listed, Grep reference/projects/ (including archive/), then the old projects.md or reference/legacy/.

| Status | Updated | Project | File | Keys |
|---|---|---|---|---|
| active | 2026-11-10 | Pages sharing password | pages-sharing-password.md | zylos-pages, share-password |
```

Rows sort by active, planning, paused, completed, abandoned, then by Updated
descending within a status. Titles are copied from pages with `|` replaced by
`／`. Unreadable headers are excluded from the main table and listed under
`Unparsable page headers`. Missing indexes are treated as empty directories
until rebuild creates them. INDEX warns above 16 KiB and has a 32 KiB budget;
page files have no hard size cap.

## Lifecycle rules

1. A project is scoped work, not a committed design choice (use
   `reference/decisions/`) or an uncommitted idea (use `reference/ideas.md`).
   One-off tasks belong in state.
2. Read the whole page before updating its Status and Updated, then append a
   dated result. Do not copy whole state blocks into project history.
3. Origin Sync or single global Sync judges whether a project is done or
   abandoned and untouched for about a month, then runs
   `reference-index.js archive --path reference/projects/<page>.md`.
   Paused projects stay in the current directory. No script enforces an age rule.
4. When an archived project is mentioned again, run
   `reference-index.js unarchive --path reference/projects/archive/<page>.md`
   before updating it. Both moves rebuild the indexes. An existing destination
   returns `EXISTS` without overwriting; rename or merge the pages before retrying.
